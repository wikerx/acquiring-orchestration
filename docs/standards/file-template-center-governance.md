# 系统文件模板中心治理规范

## 1. 适用范围

本规范约束管理系统、商户系统中提供给用户下载并用于后续导入、填写、签署或对接的**文件模板**。模板维护入口固定为：

```text
系统管理
└── 模板中心
```

以下对象不属于本规范管理范围：

- 邮件正文模板、短信正文模板；
- 费用方案、路由方案、角色授权树等业务配置“模板”；
- 查询结果导出、失败明细、结算凭证等运行时结果文件；
- 商户密钥、证书、接口文档和商户上传的合规资料。

静态模板下载不需要异步化。只有需要查询、聚合或生成大量业务数据的导出才必须进入异步下载中心。

## 2. 强制数据模型

所有文件模板必须进入以下三张表，禁止业务模块自建并行模板表：

| 表 | 职责 | 可变性 |
| --- | --- | --- |
| `sys_file_template` | 稳定编码、隶属系统、模块、下载文件名、权限、当前版本指针 | 元数据可 CAS 修改；编码和扩展名不可修改 |
| `sys_file_template_version` | 单模板递增版本、字段协议版本、发布状态、原因和操作人 | 文件内容相关字段不可修改；仅发布状态可变化 |
| `sys_file_template_asset` | `zh-CN`、`en-US` 文件摘要和私有对象定位 | 创建后不可更新、不可删除 |

数据库迁移必须同时提供：迁移脚本、前置检查、后置检查和安全回滚脚本。数据库触发器必须阻止模板稳定身份、版本内容和资产被绕过应用服务修改。

## 3. 稳定编码与文件名

- `templateCode` 是代码唯一允许持久引用的模板身份，格式为大写字母、数字和下划线，例如 `RISK_BLACK_CARD_IMPORT`。
- 中文名称等于中文下载文件的**基础文件名**，英文名称等于英文下载文件的**基础文件名**，两者都不包含扩展名。
- 下载时由服务端按定义自动拼接扩展名。浏览器、业务页面不得自行拼接或覆盖正式文件名。
- 模板编码和文件扩展名创建后不可修改。需要改变格式时创建新模板编码，并显式迁移消费方。
- 隶属系统只允许 `ADMIN`、`MERCHANT`、`SHARED`。共享模板必须分别配置管理系统和商户系统的业务权限，禁止复用一个权限编码。

## 4. 版本与发布

- 每次上传必须同时提供 `zh-CN` 和 `en-US` 两份资产；两份资产必须为同一扩展名。
- 上传接口必须携带稳定 `requestId`。同一模板的相同 `requestId` 重试只能返回原版本，不得创建重复版本。
- 上传后状态为 `DRAFT`；只有显式发布后才能下载。
- 发布和回滚必须携带模板定义的 `expectedTemplateVersion`、稳定 `requestId` 和必填原因，使用 CAS 更新当前版本指针。
- 发布版本必须同时存在两种语言资产。当前版本指针不得指向其它模板的版本或非 `PUBLISHED` 版本。
- 历史版本正文不可覆盖。回滚是重新指向历史已发布版本，不是重新上传同名文件。
- 正式下载使用当前定义的本地化基础文件名；历史版本如开放下载，文件名必须追加 `_v{versionNo}`。

## 5. 对象存储

- 模板正文必须保存到独立私有 Bucket，默认 `vexra-template-files`。
- Nacos 配置键为 `acquiring.object-storage.template-bucket`。生产环境必须显式配置并预创建 Bucket。
- 对象键固定遵守：

```text
templates/{system}/{module}/{templateCode}/{versionNo}/{locale}/{uuid}.{extension}
```

- 数据库只保存对象定位和 SHA-256；任何 API、DTO、日志和前端页面都不得暴露 Bucket、Object Key、Endpoint、Access Key 或 Secret Key。
- 下载必须经后端鉴权并校验 SHA-256，禁止公共读、永久预签名链接和浏览器直连对象存储。
- 数据库事务回滚时必须补偿删除本次已上传但未提交的对象。已发布资产禁止物理删除；归档、保留和对象生命周期策略必须单独审批。

## 6. 文件安全

- 当前允许扩展名：`xlsx`、`csv`、`pdf`、`docx`、`zip`；禁止可执行文件、脚本和 Office 宏。
- 服务端必须以文件签名、Office 容器目录或 UTF-8 解码结果识别类型，不信任浏览器 MIME 和扩展名。
- ZIP 类文件必须限制条目数和解压总体积，拒绝绝对路径、`../`、空字节和异常压缩包。
- 文件名必须移除路径、控制字符和响应头注入字符。
- 下载响应必须包含 `Content-Disposition`、`X-Content-Type-Options: nosniff` 和禁止缓存的响应头。

## 7. 权限与系统边界

- `service-admin` 拥有模板定义、上传、发布、回滚和管理端下载能力。
- `service-merchant` 只允许读取 `MERCHANT` 或 `SHARED` 的当前发布版本，不得上传、修改、发布或读取管理系统专属模板。
- 通用下载权限与模板定义上的业务权限必须同时满足。模板定义上的管理系统权限和商户系统权限相互独立。
- 旧业务路径保留时只能作为兼容适配器，必须保持原权限并委托模板中心，不得继续维护第二份文件正文。

## 8. 开发约束与自动化门禁

新增或修改模板功能时必须同时完成：

1. 在模板中心登记稳定编码、隶属系统、模块、双语文件名、扩展名和双系统权限；
2. 上传双语初始版本并发布；
3. 业务页面只按模板编码调用通用下载接口；
4. 下载端点标记 `@ManagedFileTemplateEndpoint`；
5. 兼容旧路径时标记 `@LegacyFileTemplateAdapter`，填写编码规则和最迟移除日期；
6. 添加或更新契约测试、SQL 后置检查和回归用例。

以下做法一律禁止：

- 在 `resources`、前端 `public`、本机目录或业务模块对象存储前缀散落正式模板；
- 新增一个直接生成模板正文的 Controller；
- 用中文名称、英文名称或文件路径作为业务身份；
- 覆盖已发布版本文件；
- 为绕过权限直接返回对象存储 URL；
- 把模板下载错误地接入异步导出任务。

CI 契约测试必须扫描管理系统和商户系统 Controller：新增包含 `template` 的文件下载路径但没有治理注解时构建失败；兼容标记超过 `removeAfter` 日期时构建失败。

## 9. 现有模板迁移

- 风控 BLACK、WHITE、AML、RULE 和交易加黑导入模板必须按具体功能编码登记为初始版本。
- 迁移期间旧 URL 和原权限保持不变，但返回内容必须逐步切换为模板中心当前发布资产。
- 迁移完成后删除运行时模板生成代码；导入解析协议必须继续由字段协议版本和测试保护，不能因文件替换改变既有列语义。
- 任何尚未迁移的旧端点都必须有明确兼容注解和到期日，不得把“暂时兼容”变成永久旁路。

## 10. 发布检查清单

- [ ] 三张表、四个不可变触发器、菜单和权限后置检查全部通过；
- [ ] 私有 Bucket 已创建，管理端与商户端只获得最小所需访问权限；
- [ ] 中英文文件名不含扩展名，下载响应自动拼接正确后缀；
- [ ] 上传重试、发布重试、CAS 冲突、回滚和摘要不一致均有测试；
- [ ] 管理系统无法下载无权模板，商户系统无法读取 `ADMIN` 模板；
- [ ] 旧路径权限、文件名和导入列协议回归通过；
- [ ] Controller 治理契约测试通过，且没有过期兼容适配器。
