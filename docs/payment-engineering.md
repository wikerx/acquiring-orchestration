# 跨境支付系统工程约束

## 核心领域

系统初期建议围绕以下领域拆分：

- 商户与产品配置
- 支付订单与交易状态机
- 渠道路由与渠道适配
- 风控、KYC、AML 协同
- 汇率、手续费、限额
- 清结算、对账、差错处理
- 通知、补偿、重试和人工工单

## 资金安全

1. 所有支付请求必须有全局唯一请求号和业务幂等键。
2. 状态机只允许显式合法流转，禁止任意状态覆盖。
3. 金额、币种、汇率、手续费必须在交易快照中留痕。
4. 渠道回调必须验签、校验金额币种、校验订单归属。
5. 资金相关操作必须可审计、可追踪、可重放验证。

## 跨境合规

1. 根据业务范围预留 KYC、AML、制裁名单、限额和地区策略扩展点。
2. 敏感数据按最小化原则采集、存储和展示。
3. 卡信息、证件信息、账户信息必须脱敏和加密。
4. 日志与报表不得输出完整敏感数据。

## 稳定性

1. 渠道调用必须设置超时、重试、熔断和降级策略。
2. 异步任务必须可重放、可补偿、可观测。
3. 对账任务必须支持断点续跑和差错闭环。
4. 核心链路需要指标：成功率、失败率、处理中数量、渠道耗时、重试次数、差错数量。

## 设计评审触发条件

以下变更必须先做设计评审：

- 新增支付方式或新渠道。
- 交易状态机变更。
- 资金清结算逻辑变更。
- 风控、合规、限额策略变更。
- 数据库核心表结构变更。
- 密钥、签名、加密、权限模型变更。
